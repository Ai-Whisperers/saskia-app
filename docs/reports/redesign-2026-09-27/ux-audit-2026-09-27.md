# Saskia RMS — UX/UI Pattern Audit (2026-09-27)

**Scope:** All 82 page PNGs in `docs/user-guide/screenshots/all-pages/` (shoot run 18:25 UTC).
**Method:** Vision audit of 17 representative pages covering every page family, then cross-mapping.
**Reader:** Designer planning the redesign batches (per `docs/plans/redesign-2026-09-26/00-MASTER-PLAN.md`).

## Section 1 — Per-page top patterns and defects

This section goes page-by-page. Each entry has:
- **Top patterns:** what this page does that should be a reference for the rest of the app
- **Defects:** P0/P1/P2 issues to fix
- **Apply to:** where else these patterns (or fixes) should land

### 1.1 `/` — Inicio (dashboard)

**Top patterns**
1. **Quiet "what changed since yesterday" strip at the top** — KPI tiles for ventas / merma / alertas with delta arrows. Best at-a-glance screen in the app.
2. **Two-column "Hoy" + "Esta semana" summary** with collapsible sections — minimizes scrolling for the most-checked counters.
3. **Persistent Nuevo (FAB) action in top-right** — always reachable, follows eyes to the corner.
4. **Bottom-status bar (`Saskia RMS v1.0 · Sistema local · estado · guía · ©`)** — gives ops a single confirmation that env is right.
5. **In-page "Próximo paso" CTA** ("ver tareas pendientes") — non-nagging but always-visible.

**Defects**
- P1 — KPI delta arrows render but the absolute delta number is missing in some tiles ("← 0 ventas" reads "0 ventas"). Designer: keep arrow only when number is non-zero.
- P2 — Top bar mixes search, theme toggle, and ⌘K hint on one line; on a tablet view (1024px) the ⌘K chip overlaps the date pill.

**Apply to** — every page. The `page_header` macro already encodes this, but the **delta-arrow-conditional** rule isn't.

### 1.2 `/dashboard` — legacy dashboard

**Top patterns**
1. **Sticky chart strip** with sparklines per channel (POS vs pedidos vs delivery).
2. **Day-of-week heatmap** for "cuándo vendo más" — high-leverage for production planning.
3. **Module-by-module tile grid** — each tile carries (title, micro-chart, link).

**Defects**
- P0 — This page now **duplicates** `/` and `/analisis` with no differentiating role. Three places to look for the same data.
- P1 — Heatmap is data-rich but visually mute; needs axis labels (current implementation has them but they're truncated).
- P2 — Channel sparklines use the same green/red convention as /inicio but with different color tokens.

**Apply to** — consolidate. Either (a) delete `/dashboard` and route the legacy link to `/analisis`, or (b) re-scope `/dashboard` to **only the production-side KPIs** (plan vs actual, weekly forecast) and let `/` own the POS/day-summary.

---

### 1.3 `/ventas` — POS

**Top patterns**
1. **Three-zone split-pane** — left: quick-action products (chips), center: cart builder (table with rows), right: payment + total. Designed for two-thumb counter use.
2. **Big total** on the right rail (Gs. 12.000) — never tucked away.
3. **Payment method chips** (Efectivo, Transferencia, Mixto, Tarjeta) with one-tap toggle.
4. **Keyboard shortcuts** hinted subtly (⌘K for search, numeric keypad for qty).
5. **Recent customers** strip below the cart — counter staff don't have to retype names.

**Defects**
- P1 — Quick-action product chips have **no category labels**; "garrafa" appears next to "pancho" with no grouping. Add category color-borders or inline dividers.
- P2 — Customer strip pulls from `/clientes` but shows "0 visitas" — counter has no signal which is a repeat customer.

**Apply to** — `/pedidos/nuevo` (use the same 3-zone split-pane) and `/inventario/nuevo` (collapse to a 2-zone form+sidebar when stock is >0).

### 1.4 `/inventario` — inventory list

**Top patterns**
1. **Grouped filter rail** (categoría, estado, stock range) with **chips that show what's applied** (× Harinas × Bajo mínimo).
2. **Severity color-coding on rows** — sin stock = red bar, bajo = amber, ok = subtle.
3. **Inline "sospecha" badge** (e.g. price jumped 40% in 7d) — surfaces data-quality issues.
4. **Bulk-action bar appears on row-select** with "Ajustar stock", "Marcar" actions.
5. **Density toggle** (compact / comfortable) — counter ops prefer compact.

**Defects**
- P1 — Filter rail is **left-aligned and full-height**; on narrow viewports it pushes the table under the fold.
- P2 — The "sospecha" badge is excellent UX but only renders for ingredients with a recent price change — needs a date range picker.

**Apply to** — `/productos`, `/recetas`, `/clientes` all need the same filter-chip pattern. The bulk-action bar should be a shared `_components/atoms/bulk_action_bar.html` macro.

---

### 1.5 `/recetas` — recipes list

**Top patterns**
1. **Search-with-typeahead** in the header (not just the global search) — names are unique enough that fuzzy search works.
2. **Cost & yield columns** with integer Gs. and "porciones" unit — production-relevant at a glance.
3. **Dietary pill cluster** at row end (VG, S/TACC, Keto) — derived from ingredient allergens.
4. **Status chip** (Borrador / Activa / Archivada) — color-graded.

**Defects**
- P1 — Cost column says "Gs. 75" but doesn't say **per porción** — designers should add a unit hint tooltip.
- P2 — Sort headers exist (`↑↓` arrows) but the active column doesn't show a bold highlight — designer should mirror the active nav-state convention (`.is-active`).

**Apply to** — `/inventario` (add similar dietary-derived pill cluster for ingredientes), `/productos` (chips for "sin TACC" etc.), `/merma` (severity pill cluster).

---

### 1.6 `/pedidos` — orders list

**Top patterns**
1. **Status pill** at row leading edge with color-coded urgency.
2. **Customer-name inline** as link (no separate column).
3. **Total amount** right-aligned, always shown.
4. **Fecha de entrega** with relative-time chip ("entrega hoy" / "en 3 días" / "vencido").

**Defects**
- P1 — Filter by status requires opening a dropdown — for a counter that wants "solo pendientes", a chip toggle would be faster.
- P2 — No bulk actions; selecting a row does nothing visible.

**Apply to** — `/ventas/historial` should mirror the relative-time chip pattern (entrega, hace 2 días, etc.).

### 1.7 `/productos` — products list

**Top patterns**
1. **Prime cost column** (costo / precio) as a percentage — production-and-finance-relevant.
2. **Margin % badge** with green/amber/red thresholds.
3. **Stock dot** next to SKU (✓ in stock, ⚠ low, ✗ out).
4. **IVA pill** (10% / Exento / 5%) — small but easy to scan.

**Defects**
- P1 — Some products show `Gs. 75` without the `Gs.` prefix when row density is compact — this is the voseo/format drift mentioned in §2 of the system prompt.
- P1 — Prime cost > 100% (i.e. cost exceeds price) renders as amber not red — wrong severity; should be hard red.
- P2 — "Editar" button is far right; with many columns the table is wide.

**Apply to** — `/recetas/{id}/editar` (same margin/cost columns), `/reportes/margenes` (use the same severity thresholds), `/inventario` (margin is recipe-derived but useful here too).

### 1.8 `/recetas/{id}/editar` — recipe edit (the most complex form)

**Top patterns**
1. **Side-rail "Desglose de costo"** that **updates as the user types** — immediate feedback for ingredient changes.
2. **Ingredient rows with inline delete + drag handle** — JS-driven but no external lib.
3. **Sub-recipe lines** shown alongside ingredient lines (mismo data table — no second component).
4. **Photo upload** as a discrete card with placeholder state ("Sin foto — subí una para que se vea en el POS").
5. **Derived tags block** ("Etiquetas derivadas de ingredientes — se mantienen solo si todos los insumos las cumplen") — this is the **most elegant** piece of UX in the app.

**Defects**
- P1 — Form is **2-column but the left column is the form and the right is the side rail** — long form still requires scrolling. Designer should split form into "Datos básicos / Ingredientes / Costeo / Etiquetas" tabs OR use a wizard.
- P2 — The "Canceladas" warning ("▶ Canceladas (10) — ver por qué") is collapsible but the icon doesn't change state when open.

**Apply to** — `/inventario/{id}/editar` (same derived-state pattern for "Alérgenos calculados" already exists), `/productos/{id}/editar`, `/clientes/{id}/editar`.

### 1.9 `/inventario/{id}` — ingredient detail

**Top patterns**
1. **Four-quadrant card grid** (Stock actual / Clasificación / Conservación / Precio) — at-a-glance everything ops needs.
2. **"Usado en recetas"** mini-table — surfaces the inverse relationship.
3. **"Pronóstico — ¿cuándo me quedo corto?"** block with `días restantes · horizonte · estado` — predictive, not just historical.
4. **Action button cluster top-right** (`+ Ajustá stock` outlined, `Editá ingrediente` solid) — proper secondary/primary hierarchy.
5. **Empty state for variantes** with onboarding CTA ("Sin variantes registradas. Podés agregar marcas o tamaños y marcar una como preferida") — exemplary empty-state copy.

**Defects**
- P0 — **(P0)** Pronóstico block renders `(sin consumo reciente)` and `—` for días restantes when there's no data. This is a real UX fail — should show "Pronóstico no disponible: registra movimientos de stock para activar" with a CTA to log a movement.
- P1 — HACCP "Conservación" card shows Temperatura (15-25°C), Humedad Máx (70%), Lead Time (3 días) — but there's no `edit-link` per field; if you want to fix one, you have to scroll up and Editá ingrediente.

**Apply to** — `/productos/{id}` should use the same four-quadrant card pattern. `/clientes/{id}` could use it too (visitas / gasto total / puntos / tier).

### 1.10 `/produccion-planner` — production planner

**Top patterns**
1. **Day cards** with suggested-batch computation (`plan` vs `stock`).
2. **Cost preview per recipe** — shows the financial impact of the planned batch.
3. **Two columns: "Esta semana" + "Próxima semana"** — at-a-glance.
4. **Action buttons** per day: `Regenerá plan`, `Marcá hecho`, `Saltá`.

**Defects**
- P1 — Day cards show **only one recipe per day** by default; you can scroll within a card but the inner-list affordance is subtle.
- P1 — Date headers say "Martes 28/9" but not "semana X de Y" — needs the production-week context.
- P2 — Cost preview updates server-side; after a quantity change, the page reloads fully.

**Apply to** — `/produccion` (regular board view), `/shopping-list` (regenerate from here?), `/reorder` (similar planner UX).

### 1.11 `/reportes` — reports index

**Top patterns**
1. **Grouped card list** (Operación / Catálogo / Finanzas / Clientes) with icon + title + 1-line description.

3. **Sticky sub-nav** under the main nav: "Operación / Catálogo / ..."

**Defects**
- P1 — Many cards show the same icon (📊) — designers should differentiate by report family (line chart, table, bar).
- P1 — Search-bar for reports is missing — at 15+ reports this needs it.
- P2 — Some report descriptions are copy-pasted across cards.

**Apply to** — `/guia` (numbered section nav already exists but lacks search), `/settings` (also needs a search for sub-settings), `/ops/status` (if it grows).

### 1.12 `/analisis` — analysis page

**Top patterns**
1. **4-KPI panorama strip** at the top (Capital en inventario / Hora pico / Día pico / Costo de materia prima %).
2. **Sectioned insight blocks** with explicit "what to read this as" subtitle: "Estrellas (alto margen + alto volumen)", "Para revisar (bajo margen + bajo volumen)", "Productos más rentables (últimos 30 días)".
3. **Promedio de ventas por día de la semana** — perfect for production planning.
4. **Rotación de stock (últimos 30 días)** with `días de stock` column — gives ops a number to act on.
5. **Empty-state handling** for Levadura seca and Ingrediente 415de24c (both show `0.0 kg`, `0.0×`, `—`) — but doesn't say why. **Defect P0** here.

**Defects**
- P0 — Rotation block shows `0.0 kg / 0.0× / —` for two ingredients with no clear CTA to fix the data — should say "Sin movimientos de stock registrados. Empezá registrando una compra o un consumo."
- P1 — "Estrellas" / "Para revisar" cards have **left-edge color stripes** but the colors (green, amber) are only the lightest tints — needs more contrast for ops eyes at-a-glance.
- P2 — Bar chart for "Promedio de ventas" is missing — it's a table only. The data is exactly the kind that benefits from a small inline bar.

**Apply to** — `/reportes/top-productos` (mirror the insight-block pattern with subtitle), `/dashboard` (consolidate the KPIs here), `/inicio` (surface 1-2 insights as a "Para revisar" widget).

- P2 — The orange "Guardar" button is at the very bottom — users don't know if changes are auto-saved.

## Section 3 — Universal defects (apply app-wide)

These problems showed up in 4+ pages and should be fixed at the template/style level rather than page-by-page.

### D1 — Native date picker still visible (P1, multi-page)
**Affected:** `/reportes/top-productos`, `/merma`, `/inventario/nuevo`, `/settings`
**Symptom:** Default browser date picker (white-on-white triangle, English locale "mm/dd/yyyy" placeholder).
**Fix:** Web Component `<saskia-date>` with voseo-paragraph placeholders ("día/mes/año") and the dark-mode tokens. AGENTS.md already forbids this bleed-through but enforcement is incomplete.

### D2 — "Editar" / "Ver" button row too far right on wide tables (P2)
**Affected:** `/clientes`, `/suppliers`, `/proveedores-alias`, `/inventario`, `/productos`
**Symptom:** Action button is column 8+ on wide tables; first-time users miss it.
**Fix:** Sticky-right action column (always-visible regardless of scroll), OR move actions to row-leading position with a chevron `›` affordance.

### D3 — Currency rendering drift — sometimes `Gs. 75`, sometimes `75`, sometimes `Gs. 75,00` (P0)
**Affected:** All /reportes/* pages, /productos, /recetas/{id}, /bank
**Symptom:** Same data rendered with three different formats depending on context.
**Root cause:** Some templates call `format_gs` filter, some inline-format, some leave the raw int.
**Fix:** Mandate `format_gs` Jinja filter everywhere; lint with a grep rule that fails CI if `Gs\. {{` or `Gs. {{` appears without the filter. (See §2 Prime Directive #5 of system prompt — this is the recurring failure.)

### D4 — "Cargando..." spinner never replaced with content on slow routes (P1)
**Affected:** /reportes/*, /analisis (long compute)
**Symptom:** Skeleton spinner stays even after data returns.
**Fix:** Confirm `app-components.js` mutation observer is attached to all async-bound elements.

### D5 — 0 visitas / 0 ventas / 0 merma ambiguity (P1)
**Affected:** `/clientes`, `/ventas/historial`, `/merma`, `/analisis` rotación
**Symptom:** "0" rendered as text doesn't distinguish between (a) genuinely zero and (b) no data yet.
**Fix:** Render "—" for "no data" and "0" for "zero data". Server should pass `value=None` vs `value=0`.

### D6 — Seed-name identifiers leak into UI ("Producto cfaf4b47", "Receta 0da4ca66") (P0)
**Affected:** `/reportes/top-productos`, `/analisis`, `/vs-mercado`
**Symptom:** The seed fixture uses `cfaf4b47` and `0da4ca66` as names; they appear in UI.
**Fix:** Seed fixture should generate human-readable names ("Pan de queso", "Chipa grande") — this is a test-data bug, not a UI bug, but designers will trip over it. Auto-create a Spanish bakery-name pool in the seeder.

## Section 6 — Open questions for the designer

Before the next batch ships, the designer should confirm:

1. **Should `/dashboard` be deleted?** It's now redundant with `/` and `/analisis`. If we keep it, what's its unique role? Recommendation: **delete**; add `/dashboard → /` redirect.
2. **Where should the live "today" KPIs live?** Currently on `/` only. If we move them to `/analisis`, the `inicio` becomes a "todo list" view (pending orders, low stock, recent ventas). Recommendation: **split**: `/` = actionable (orders pending, stock low); `/analisis` = strategic (KPIs, trends, forecasts).
3. **Should recipes be the product?** Recipes are the heart of the system (productos are "what we sell", recetas are "how we make it"). The UI currently treats them as siblings under "Catálogo". Recommendation: **make recetas the primary entity** and productos the derived commercial entity — refactor nav accordingly in v2.
4. **What's the canonical filter rail pattern?** Two pages currently do this differently (`/inventario` = chip rail, `/productos` = dropdown). Recommendation: **chips everywhere** with one "advanced filters" disclosure if needed.
5. **Should `/riesgos` ship before production?** It currently renders nothing. If it's a v2 feature, gate it behind a flag; if it's v1, fill it out.
