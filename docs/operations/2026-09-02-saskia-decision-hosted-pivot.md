## 4. The hard problems (and how we handle them)

### 4.1 What if Neon / Supabase / Cloudflare changes free-tier terms?

The stack is portable. Migration scripts:

- **DB:** `pg_dump` from Neon, `pg_restore` to RDS / Supabase / your-VPS. Schema is plain SQL.
- **Auth:** swap Supabase for bcrypt-only (already supported via `using_supabase()` toggle in `auth.py`)
- **App host:** Fly.io is the documented alternative (`fly.toml` is committed)
- **Tunnel:** Caddy + Let's Encrypt is a 30-line replacement if CF Tunnel goes paid

### 4.2 What if Render's free tier spins down?

UptimeRobot pings `/healthz` every 5 min → Render never idles. Verified 2026-09 by AIW: free tier spin-down is 15 min idle, UptimeRobot interval is 5 min → no spin-down in practice.

### 4.3 What about real-world latency from Paraguay?

- Neon US East → Paraguay: ~180-220ms RTT (acceptable for an internal business tool)
- Render Oregon → Paraguay: ~220ms RTT
- Cloudflare edge (anycast) → Paraguay: ~30-50ms RTT for static, ~100ms for dynamic

If latency matters: use Fly.io São Paulo region (`primary_region = "gru"` is already in `fly.toml`). São Paulo → Paraguay is ~50ms RTT. Combined with a São Paulo Neon project, total round-trip can hit ~100ms.

### 4.4 What if Saskia loses her phone?

Password reset flow exists (`POST /forgot-password` → Supabase sends email). She needs to remember her email address (we control this — use `saskia@paragu-ai.com` or whatever).

### 4.5 What if her data gets corrupted?

Two layers:
- Neon PITR (point-in-time recovery, included in free tier, 7-day window)
- Daily R2 encrypted snapshot (already implemented in `app/services/backup_scheduler.py` + `app/services/r2_backup.py`)

Both are automated. We test this in Milestone 1 acceptance.

### 4.6 What does it cost?

| Item | Cost | Notes |
