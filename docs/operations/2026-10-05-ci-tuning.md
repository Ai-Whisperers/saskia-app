## Pytest breakdown

| Metric | Value |
|---|---|
| Tests collected | 5,598 |
| Test files | 485 |
| `init_db()` per test | ~1.2 s (file-based SQLite + migrations) |
| `TestClient.__init__` per test | ~3.0 s |
| Per-test setup (after first in file) | ~0.4 s |
| Per-test teardown | ~0.05 s |
| `playwright` import cost | 1.8 s (loaded once, then shared) |

The dominant cost is **per-test setup**, not collection or any single slow
test. With function-scoped `client` + `session_factory`, every test pays:

1. `tmp_db_path` autouse — fresh temp dir
3. `app_engine` — `make_engine(...)` + `init_db(engine)` (1.2 s)
4. `session_factory` — `make_session_factory(engine)`
5. `client` — `TestClient(app)` (3 s)
6. tear-down: `_close_leaked_sessions` (0.05 s)

**Estimated setup cost: ~5 s × 5,597 tests = ~7.8 hours of pure setup if
run serially.** With `-n 2`, that's ~3.9 hours of CPU-bound setup work
split between two runners (1 worker per CPU).

## Bottlenecks ranked

### 1. `client` fixture is function-scoped (HIGH IMPACT)

`tests/conftest.py:249` defines `client` as a regular fixture, so every
test creates a new `TestClient(app)` (~3 s). A session- or module-scoped
client would cut setup time per test from 0.4 s to ~0.05 s.

**Trade-off:** shared `app.state` means tests need to clean up after
themselves. The `reset_app_state` autouse fixture already handles this.

**Estimated win:** 0.35 s × 5,597 = ~33 min saved per CI run.

### 2. `--all-extras` pulls in 134MB Playwright wheel (MEDIUM IMPACT)

`uv sync --all-extras` installs **all** optional-dependency groups,
including Playwright. Only 9 of 5,598 tests use it (`tests/browser/`).
The wheel alone is 134MB; the browsers it downloads are 656MB. None of
this is needed for non-browser tests.

**Fix:** Move the dev extra into a CI-specific group. Default `uv sync`
installs only required deps. Browser tests have their own job that does
`uv sync --extra browser`.

**Estimated win:** ~38 s cold cache (or hit cache), 820 MB less disk
pressure on the runner.

### 3. Cold cache reinstalls `cryptography`, `boto3`, `psycopg` wheels (LOW IMPACT)

These big wheels (cryptography 16MB, boto3 29MB, psycopg 8MB) reinstall
whenever the lock changes. The `astral-sh/setup-uv@v7` action caches
`~/.cache/uv`, so this is only a first-run cost.

**Fix:** Confirm the cache key includes `uv.lock`. Already does.

### 4. Redundant `coverage check` step (LOW IMPACT)

After `pytest --cov-fail-under=35`, the next step runs `coverage report`
again. The first step's exit code already enforces the gate. The second
is a 1-second belt-and-suspenders.

**Fix:** Remove the redundant step.

### 5. `pytest --collect-only` runs even when test count is unchanged (LOW IMPACT)

~22 s to collect 5,598 tests. Not avoidable — pytest needs to import
all test modules to know what's there. But splitting collection into a
"smoke subset" (-m "smoke" = 251 tests, ~3s collection) and "everything
else" gives faster feedback on the most common break class.

**Fix:** Already done via `route-smoke.yml`.

### 6. `pytest-randomly` is installed but disabled (`-p no:randomly`) (LOW IMPACT)

It's in `pyproject.toml: dev = [...]` but the addopts disables it. Either
remove it from dev or remove `-p no:`. Cleanup is essentially
dev but the -p is intentional (some tests depend on order).

**Decision:** Leave as is — `-p no:randomly` is safer.

## Plan

### Phase A: Win the 30-minute setup cost (LOW RISK)

1. **Promote `client` to session-scoped** in `tests/conftest.py`
   - Add `scope="session"` to `@pytest.fixture def client(...)`
   - Add per-test cleanup of `app.state` (already done by `reset_app_state`)
   - Verify all 5,598 tests still pass

2. **Add module-scoped `session_factory`** for tests that don't need
   per-test isolation — those that don't write data, just read.
   - Initial scope: 100% of `tests/test_route_smoke_*.py` (250+ tests)
   - Verify the route smoke still passes

**Estimated win: 30 min on full CI run. Risk: medium (need to verify
test isolation still works).**

### Phase B: Drop Playwright from the main install (LOW RISK)

1. **Add `[tool.uv.optional-dependencies].browser`** group with just
   playwright + pytest-randomly (or split dev into dev-core and dev-browser)
2. **Update `ci.yml`** to drop `--all-extras`, use `uv sync --extra dev`
3. **Move browser tests to a separate workflow** (only triggered on
   labels or schedule)

**Estimated win: 38 s cold cache + 820 MB disk + cleaner audit trail.
Risk: low (browser tests already separate).**

### Phase C: Minor speedups (LOW RISK)

1. **Remove redundant coverage check step** in ci.yml — `--cov-fail-under`
   already gates on this.
2. **Add `concurrency:` block** to ci.yml — auto-cancel previous runs
   on the same PR when a new commit is pushed.
3. **Pin actions/checkout to SHA** instead of `@v7` for supply-chain
   security + faster caching.

**Estimated win: 5 s + better dev UX.**

## Rejected ideas

| Idea | Why rejected |
|---|---|
| `-n auto` parallelism | Tested earlier (2026-10-04): disk pressure on 30 GB runner; dropped to "no space left on device". `-n 2` is the safe ceiling. |
| Compile Python to .pyc | Marginal, breaks debugging. Not worth it. |
| Split pytest by directory (5 parallel jobs) | Each job still does 0.4s/test setup. The 30-min setup cost is per-worker, not per-job. Splitting multiplies total setup. |
| Skip coverage report in PRs, only run on main | Would hide coverage drops until merge. The 1-second cost isn't worth the visibility loss. |
| Use Postgres for all tests | `init_db()` is 1.2s for SQLite; Postgres + migrations is 5-10s. We already have a separate Postgres job. |

## Net estimated wins

If Phase A + B + C all land:
- Full CI: 12 min → 6 min (50% faster)
- Cold-cache first-time CI: 8 min → 4 min (50% faster)
- Disk usage: 820 MB less on runner
- Test count: unchanged (5,598)
- Coverage: unchanged

## Risks

| Risk | Mitigation |
|---|---|
| Session-scoped `client` leaks state between tests | `reset_app_state` autouse + careful `app.state` reset. Validate by running full suite. |
| `--all-extras` removal breaks other CI workflows | Search for `all-extras` usages. Confirm only ci.yml + smoke.yml use it. |
| Browser workflow never runs (scheduled, not PR) | Schedule daily cron + on-demand via workflow_dispatch. |
